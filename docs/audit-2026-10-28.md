## Scope dan tingkat kepastian

- Audit mencakup **working tree yang dirty**, termasuk source untracked; bukan hanya commit baseline. Banyak pekerjaan UI/backend sudah ada sebelum audit. Temuan bukan atribusi kepada commit atau pengembang tertentu.
- Inventaris utama: `app`, seluruh enam modul yang mempunyai manifest (`Master`, `Transaction`, `Pos`, `Crm`, `Report`, `Chat`), routes, config, database, views, assets, tests, dependency/build metadata, serta dokumentasi. `infruity-frontend` dibaca sebagai referensi; tidak dimodifikasi.
- Analisis berupa penelusuran route–middleware–controller–model–view, refleksi target controller, compile query tanpa eksekusi DB, probe validasi offline, hash duplikasi, lint, dan suite test terisolasi. Pemeriksaan source diparalelkan dan temuan utama dibaca ulang sebelum laporan digabung.
- Tidak menjalankan reset, pengiriman FCM, pembayaran, finalisasi, migration, atau operasi bisnis terhadap database dev/produksi. Penulisan data pada suite berlangsung dalam fixture SQLite in-memory.
- Tidak melakukan pengujian penetrasi HTTP produksi, browser E2E, pengukuran performa/EXPLAIN database bisnis, pemeriksaan access log, atau pembuktian concurrency MySQL. Exposure deployment dan permission akun aktual belum diperiksa.
- **Tinggi** berarti dampak potensial besar berdasarkan alur aktif; tidak berarti sudah terjadi eksploitasi. Temuan berpermission mensyaratkan akun login dengan izin tersebut. **Sedang** mencakup correctness/maintainability yang nyata tetapi lebih terbatas.
- Seluruh temuan kode di bawah **belum diperbaiki pada pekerjaan audit ini**. Perubahan pekerjaan ini hanya dokumentasi; tidak ada deletion atau refactor bisnis.

## 2. Temuan backend prioritas

### A01 — Tinggi: reset wholesale mempunyai blast radius lintas domain

**Bukti:** `Modules/Transaction/Http/Controllers/WholesaleController.php:783–826`, route `Modules/Transaction/Routes/web.php:46`.

Handler yang lolos izin **`wholesale.reset`** mematikan foreign-key checks lalu melakukan truncate pada tabel POS, pembayaran, transfer, produksi, opname, order book, expenditure, dan wholesale. Tidak ada environment guard atau pembatasan cabang. Ini fungsi destruktif berotorisasi, **bukan klaim bypass permission**. Nama dan respons endpoint mengecilkan cakupan operasi sebenarnya.

**Perbaikan minimal:** keluarkan endpoint reset dari deployment produksi. Jika reset memang diperlukan untuk development, jadikan command lokal dengan environment guard dan konfirmasi yang menjelaskan semua tabel. **Acceptance:** request pada environment production ditolak/tidak mempunyai route sebelum ada statement destruktif; tidak menguji dengan truncate database bisnis.

### A02 — Tinggi: izin update staf dapat mengubah role akun sendiri menjadi Administrator

**Bukti:** `Modules/Master/Http/Controllers/StaffController.php:165–175,194–204,351–362`; `app/Models/RoleMenu.php:75–79`.

`staff.update` mengizinkan `role_ids` apa pun yang ada pada tabel role, lalu mengganti assignment akun tertaut. Tidak ada pemeriksaan kewenangan memberi role Administrator atau larangan eskalasi diri. Jika akun nonadmin dengan izin tersebut mempunyai staf tertaut, role ID 1 dapat menjadi jalur eskalasi. Keberadaan akun/izin seperti itu pada deployment belum diperiksa.

**Perbaikan minimal:** pisahkan izin penetapan role dari CRUD staf dan batasi pemberian Administrator oleh Administrator yang berwenang. **Acceptance:** nonadmin dengan `staff.update` tidak dapat menaikkan role sendiri/akun lain; edit data staf biasa tetap berfungsi; test mencakup akun tertaut dan staff tanpa akun.

### A03 — Tinggi: pembayaran COD menduplikasi logika POS tanpa proteksi yang sama

**Bukti:** `Modules/Pos/Http/Controllers/DeliveryOrderController.php:98–145`, route `Modules/Pos/Routes/web.php:44`.

`setSelesai()` memeriksa `delivery-order.set-selesai`, tetapi lookup invoice tidak scoped cabang; pembayaran baru dibuat pada setiap request nominal positif, tanpa status guard, idempotency, atau lock invoice. `branch_id` pembayaran di-hardcode `1`; total paid menjumlahkan gross tanpa mengurangi return.

**Dampak potensial:** mutasi invoice cabang lain dan ledger pembayaran/kembalian berulang saat retry. **Perbaikan minimal:** satu action pembayaran yang dipakai POS dan COD, bukan dua implementasi. Service idempotency POS yang sudah ada adalah referensi perilaku, bukan alasan langsung memanggil controller lain. **Acceptance:** replay dan request paralel tidak menggandakan ledger; invoice lunas/lintas cabang ditolak; cabang pembayaran mengikuti invoice dan paid memakai nilai neto.

### A04 — Tinggi: mutasi detail pengadaan melewati scope cabang dan finalitas header

**Bukti:** `Modules/Transaction/Http/Controllers/WholesaleController.php:338–358,689–698`; route `Modules/Transaction/Routes/web.php:40,43`.

Halaman edit membatasi cabang/status, tetapi endpoint update/delete detail mengambil `WholesaleProduct::findOrFail($id)` langsung setelah permission check. Pengguna yang mempunyai permission terkait dapat menarget detail header lain, termasuk `complete`; model tidak menyediakan global scope cabang.

**Perbaikan minimal:** resolve detail melalui header yang sudah diotorisasi, lock header, validasi state sebelum mutasi. **Acceptance:** cross-branch dan header final ditolak tanpa perubahan; edit beradu dengan finalisasi tetap konsisten.

### A05 — Tinggi: simpan expenditure mengganti transaksi berdasarkan invoice global

**Bukti:** `Modules/Pos/Http/Controllers/ExpenditureController.php:144–188`, route `Modules/Pos/Routes/web.php:52`.

Setelah izin `expenditure.save-transaction`, cabang hanya divalidasi `nullable`; pencarian invoice global menghapus header/detail lama sebelum membuat record baru, tanpa scope cabang/ownership/final state target. Pembayaran lama tidak direkonsiliasi pada rangkaian penggantian tersebut.

**Perbaikan minimal:** gunakan identitas record yang eksplisit dan terotorisasi; update header/detail di bawah lock, bukan delete/recreate berdasarkan invoice kiriman klien. **Acceptance:** invoice cabang lain/final tidak berubah; relasi pembayaran dan identitas transaksi terjaga setelah edit.

### A06 — Tinggi: report barang buang mobile tidak menerapkan scope cabang

**Bukti:** `Modules/Report/Http/Controllers/MobileReportController.php:335–343`, route `Modules/Report/Routes/web.php:20–21`.

Cabang query `loss` tidak memanggil `scopeBranch()` seperti query sales/profit/shipping. Permission laporan tetap diperiksa, tetapi `branch_id=all` tidak membatasi cabang pengguna; ID cabang lain menjadi filter langsung. Bentuk query dikonfirmasi offline, bukan pembacaan data produksi.

**Perbaikan minimal:** gunakan helper scope yang sudah ada. **Acceptance:** pengguna cabang A hanya melihat A untuk `all`, tidak dapat membaca B; cakup endpoint dates dan history.

### A07 — Tinggi: endpoint data tidak konsisten dengan permission halaman

**Bukti:** `app/Http/Controllers/UserController.php:339–345`; `Modules/Crm/Http/Controllers/TierController.php:270–272,308–310`; `routes/admin.php:34–37`; `Modules/Crm/Routes/web.php:43–49`.

`/user/data`, `/tier/data`, dan `/customer-report/data` hanya bergantung pada login, sedangkan handler mengambil dataset tanpa pemeriksaan izin halaman bersangkutan. Melarang akses halaman tidak melarang request langsung ke data. Cakupan data deployment belum diukur.

**Perbaikan minimal:** terapkan pemeriksaan permission yang konsisten pada handler, menggunakan mekanisme access control yang sudah ada; jangan membuat sistem permission kedua. **Acceptance:** akun login tanpa izin mendapat 403 sebelum query data, sementara akun berizin tetap memperoleh response contract yang sama.

### A08 — Tinggi: route percobaan FCM dapat mengirim broadcast melalui GET

**Bukti:** `routes/admin.php:34–48`; `app/Services/FcmService.php:42–73`.

`GET /test-fcm` hanya membutuhkan auth, mengambil seluruh token perangkat, memanggil pengiriman massal tanpa izin khusus/throttle, dan selalu menyatakan terkirim walaupun service gagal. Endpoint **tidak dipanggil** dalam audit; pengiriman nyata bergantung konfigurasi FCM.

**Perbaikan minimal:** hapus route percobaan dari deployment; jika fitur diperlukan, gunakan POST berizin khusus, batas target/rate, dan response sesuai hasil. **Acceptance:** GET tidak menimbulkan side effect, pengguna biasa ditolak, service di-fake pada test.

### A09 — Tinggi: HTML raw varian tidak meng-escape nama pada atribut

**Bukti:** `Modules/Master/Http/Controllers/ProductController.php:804,814,824–827,842`; pemanggil `Modules/Master/Resources/views/products/partials/create-script.blade.php:469–499`.

Nama tersimpan masuk langsung ke `data-name="..."` pada kolom DataTables `rawColumns(['action'])`. Reviewer mereproduksi keluarnya markup tambahan melalui processor Yajra dan parser DOM offline; pembacaan ulang source mengonfirmasi concatenation tanpa escape. Eksekusi JavaScript browser/CSP dan kompromi aktual **tidak diuji**.

**Perbaikan minimal:** escape semua nilai dinamis atribut/HTML raw, misalnya `e($row->name)`; jangan sekadar mengandalkan validasi string atau front-end. **Acceptance:** nama berisi kutip/markup tetap menjadi teks/data, tidak membuat atribut/elemen baru, aksi edit tetap membaca nama asli.

### A10 — Tinggi: nominal deposito klien tidak sesuai dasar pemberian voucher

**Bukti:** `Modules/Crm/Http/Controllers/DepositoController.php:76–80,101–106`; konfigurasi seed tier `database/migrations/2025_07_01_095927_create_tier_table.php:60–68`; consumer voucher `Modules/Pos/Http/Controllers/PosController.php:386–390`.

Nominal `"0"` lolos validator yang digunakan (diulang dengan validator Laravel offline), tetapi voucher dihitung dari deposito tier, bukan nominal deposito yang disimpan. Field readonly UI tidak menegakkan aturan server. Tier deployment belum diperiksa; tidak ada deposito yang dibuat dalam audit.

**Perbaikan minimal:** tentukan nominal otoritatif dari tier di server, atau validasi nominal terhadap kontrak tier yang disetujui bisnis. **Acceptance:** nominal tidak sah/tidak sesuai tidak menghasilkan voucher; jalur tier sah menghasilkan hak yang sesuai dan tersimpan atomik.

### A11 — Tinggi: kebutuhan bahan produksi tidak akumulatif dan dicek sebelum transaksi

**Bukti:** `Modules/Transaction/Http/Controllers/ProductionController.php:93–96,114–131,173–180`; konsumsi stock pada `database/sql/transaction_stock.sql:105–119`.

ID ingredient boleh berulang dan setiap baris dibandingkan sendiri dengan stock; pembacaan berlangsung sebelum `beginTransaction()` tanpa lock. Duplikasi bahan dapat lolos secara individual padahal total kebutuhannya berlebih; request paralel membaca ketersediaan yang sama.

**Perbaikan minimal:** agregasikan kuantitas per product, cek di dalam transaksi dengan penguncian konsisten pada baris otoritatif yang disepakati seluruh writer stock. Jangan menganggap lock pada query view otomatis melindungi seluruh sumber stock. **Acceptance:** kebutuhan kumulatif berlebih ditolak; dua posting berebut stock terakhir diuji pada MySQL khusus test.

### A12 — Tinggi: finalisasi parcel dapat mengulang rangkaian produksi

**Bukti:** `Modules/Transaction/Http/Controllers/ProductionParcelController.php:480–558`, route `Modules/Transaction/Routes/web.php:132`.

Handler tidak lock parcel atau memeriksa apakah sudah `complete`; setiap panggilan membuat Product, Receipt, Production, dan detail baru, lalu mengganti `parcel.product_id`.

**Perbaikan minimal:** lock header, validasi transisi status satu kali, dan return hasil finalisasi yang sama untuk replay yang sah. **Acceptance:** panggilan berurutan maupun paralel menghasilkan satu rangkaian output; penolakan tidak meninggalkan record parsial.

### A13 — Sedang: HPP jus tidak mengisi kolom agregasi laba

**Bukti:** `Modules/Pos/Http/Controllers/PosController.php:1078–1080,1111–1126`; `Modules/Report/Http/Controllers/ReportController.php:617–619`; default schema `database/migrations/2025_06_09_083356_create_pos_transaction_table.php:63`.

Detail `jus` mengisi HPP unit tetapi tidak `subtotal_hpp`. Laporan laba menjumlahkan `subtotal_hpp`, yang default-nya nol pada migration. Jalur bulk `insert()` tidak mengandalkan model observer. Jika schema deployment sama, biaya jus tidak masuk laba sebagaimana dimaksud.

**Perbaikan minimal:** isi subtotal HPP dari HPP unit × quantity menggunakan aturan rounding domain yang sama. **Acceptance:** penjualan dari stock jadi/produksi baru/campuran menghasilkan subtotal HPP dan laporan desktop/mobile konsisten. Data historis perlu rekonsiliasi terpisah, bukan backfill otomatis saat refactor.

### A14 — Sedang: pembuatan varian tidak memenuhi relasi yang diwajibkan edit/hapus

**Bukti:** `Modules/Master/Http/Controllers/ProductController.php:839–853,886–889,912–915`; `Modules/Master/Entities/Product.php:113–115`.

Endpoint store varian hanya mengisi `products.parent_id`, tanpa `ProductChild`/flag `is_variant`, sementara edit/hapus memakai `whereHas('parentProduct')` pada tabel relasi tersebut. Varian baru tidak memenuhi lookup yang diharapkan source. Trigger database eksternal belum diperiksa.

**Perbaikan minimal:** satu helper kecil pembuatan varian yang mengisi invariant relasi/flag secara atomik untuk seluruh entrypoint. **Acceptance:** varian baru segera dapat dibaca, diedit, dan dihapus dari parent yang benar; parent lain tetap ditolak.

### A15 — Sedang: validator numeric dan normalisasi harga bertentangan

**Bukti:** `Modules/Master/Http/Controllers/ProductController.php:750–752,770–776`; UI `Modules/Master/Resources/views/products/index.blade.php:812–840`.

Probe ulang memakai validator terpasang: `"12.50"` lolos `numeric|min:0` lalu berubah menjadi `"1250"`; `"1e3"` lolos lalu menjadi `"13"` karena semua karakter non-digit dihapus. Tidak ada harga yang disimpan dalam audit.

**Perbaikan minimal:** jika domain rupiah bulat, gunakan validator integer nonnegatif dan simpan nilai tervalidasi tanpa stripping sesudahnya. Pisahkan parsing input terlokalisasi dari format penyimpanan. **Acceptance:** decimal/scientific notation ditolak atau diproses sesuai kontrak eksplisit, bukan diam-diam berubah nilai; UI dan endpoint sesuai.

### A16 — Sedang: aturan positif EXP tidak konsisten antar-entrypoint

**Bukti:** `Modules/Crm/Http/Controllers/SettingExpController.php:87–101`; form `Modules/Crm/Resources/views/setting-exp/index2.blade.php:7–14`; consumer `Modules/Pos/Http/Controllers/PosController.php:927,1012,1121`.

Endpoint pengaturan EXP menyimpan `skala`, `value`, dan perkalian tanpa validasi, berbeda dari jalur PointSchedule yang sudah membatasi nilainya. Nilai negatif dapat masuk faktor perhitungan transaksi.

**Perbaikan minimal:** bagikan rules validasi kecil pada kedua entrypoint; tidak perlu service baru hanya untuk array rules. **Acceptance:** skala nonpositif/value negatif ditolak konsisten dan nilai lama tetap utuh ketika validasi gagal.

### Q03 — Sedang: upgrade runtime belum sepenuhnya didukung quality gate

Lint PHP 8.5 menemukan deprecation pada:

- `Modules/Crm/Http/Controllers/DashboardController.php:43`: cast `(double)`.
- `Modules/Transaction/Http/Controllers/StockOpnameController.php:126,238,602`: cast `(double)`.
- `app/Libraries/GoogleAuthenticator.php:121`: interpolasi `${var}`.

Semua lolos syntax check, tetapi klaim historis "0 deprecation" tidak menggambarkan seluruh working tree saat ini. Tidak ditemukan file CI tracked pada `.github` atau `.gitlab-ci.yml`; `.gitlab-ci.yml` juga di-ignore. Ini tidak membuktikan tidak ada CI eksternal, tetapi quality gate tidak dapat direproduksi dari repo tersebut.

**Acceptance:** runner config valid, fixture mandiri, failure role/account diselesaikan sesuai kontrak, lint bersih, dan command test terdokumentasi dijalankan pada CI yang dapat diaudit. Test source-string/Node stub tidak menggantikan test perilaku endpoint/browser dan MySQL concurrency.

### Q04 — Sedang: runtime dependency/build tidak mempunyai satu sumber yang reproducible

`composer.lock` ada lokal tetapi tidak tracked dan di-ignore `.gitignore:9`. `package-lock.json` tracked, format lockfile 1; ini bukan bukti kerentanan, tetapi build legacy belum diverifikasi pada Node mesin audit. `webpack.mix.js:14–15` hanya membangun app.js/Sass legacy; UI ERP juga memakai aset langsung.

`resources/views/template/root.blade.php:47–53,131–135` memuat CDN jQuery 3.6.0 dan kemudian global bundle yang header `public/assets/plugins/global/plugins.bundle.js:2` menyatakan jQuery 3.7.1. Dua definisi runtime terbukti di source; efek overwrite/plugin perlu browser test. Layout `layouts/erp-tailwind.blade.php` mendefinisikan runtime sendiri lagi.

### Q05 — Sedang: dokumentasi onboarding tidak sesuai kode aktual
