# UI Design & Exploration Workflow

## Rule: Always Provide Standalone HTML for UI Exploration / Ambiguity
- **Kondisi:** Setiap kali pengguna bingung, ragu, atau meminta ide mengenai tampilan/desain UI baru maupun perbaikan UI yang ada ("bingung diapakan tampilannya", dsb).
- **Aksi Wajib:**
  1. **Buat file HTML terpisah** (prototipe interaktif mandiri) yang menyajikan beberapa opsi perbandingan (misal: Opsi 1, Opsi 2, Opsi 3) secara berdampingan (side-by-side).
  2. Berikan kontrol interaktif jika relevan (misal toggle switch on/off, klik tombol, dsb) agar pengguna bisa mencoba langsung feel & UX-nya.
  3. Ambil screenshot / dokumentasikan perbandingannya secara visual.
  4. Minta pilihan dari pengguna terlebih dahulu sebelum menerapkan opsi terpilih ke file utama proyek.
